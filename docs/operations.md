# Operations

Run verification using `npm run lint`, `npm run typecheck`, `npm test`, and `npm run build`. `pm2 start ecosystem.config.cjs` launches only the loopback API, not a market writer or Shadow engine. `pm2 status`, `pm2 logs btc-shadow-api`, and `pm2 restart btc-shadow-api` operate on that API only. Producer and Shadow PM2 templates are not production activation commands.
The restored-only Shadow entrypoint now exists, but refuses to start without the dedicated `bybit_shadow` OS/peer role, a pre-existing activation journal, matching `SHADOW_ACTIVATION_ID`/`SHADOW_LAUNCH_APPROVAL`, a separate policy artifact with `runtime_start_authorized=true` and frozen values, an accessible frozen Python runtime/model, a verified inverse lot size, and current reconciled source readiness. The existing `forward_shadow_policy_approval_v1.json` says `runtime_start_authorized=false` and remains unchanged; it cannot be used to start this runtime. The PM2 template does not provide these values. This code has not been launched against the production DB or approved for operational activation.
`RUNTIME_ROLE=api_probe node dist/main.js` is an optional loopback read-only public-market probe. Its health endpoint remains `not_ready`; it has no DB or inference/Shadow consumer. The default PM2 file deliberately does not enable this probe automatically.

`RUNTIME_ROLE=api_shadow_readonly` is a separate optional loopback API under the `bybit_shadow` OS/peer role. It requires `PGUSER=bybit_shadow` and an existing `SHADOW_ACTIVATION_ID`, and uses only SELECT queries. It exposes committed journal metrics and canonical DB timestamps, but deliberately reports `runtimeVerified=false`, `sourceFresh=false`, and `forwardShadowStarted=false` because neither WS connectivity nor a live supervised Shadow heartbeat is established by those reads. When the canonical DB source is stale, current marked equity and metrics are null instead of being valued from an old price. Do not publish this API externally or treat it as an activation gate. This role is not started by the PM2 template.

Public feeds: `wss://stream.bybit.com/v5/public/inverse` with `publicTrade.BTCUSD`, `kline.1.BTCUSD`, `kline.5.BTCUSD`; heartbeat is 20 seconds. No API keys. Local Python inference requires the original research environment/model path and hash verification. SMTP credentials, if ever configured, belong only in untracked runtime environment; do not put them in logs or git.

Operational blockers: administrator migration/deployment and Python→Node writer cutover, real DB/REST/WS anchor and restart validation, source freshness soak, safe frozen Python inference bundle, persistent Shadow journal/activation/restart, verified inverse quantity/liquidation rules, hourly SMTP delivery and live API process validation. The Node WRITE path exists but fails closed until a root-owned cutover marker, stopped/disabled legacy Python service, dedicated peer role, and exclusive DB session lock are present. Until closed, `FORWARD_SHADOW_STARTED=FALSE`, actual orders and private API calls remain zero.

After the reviewed journal migration is installed, an administrator may run the read-only dedicated-role check as the `bybit_shadow` OS user with `PGUSER=bybit_shadow npm run shadow:db-preflight` from the deployed runtime. It uses the local PostgreSQL socket and checks both session identity and catalog grants. It never activates Shadow or writes data. Do not run it with `btcuser`, TCP/password credentials, or before the DBA-approved migration.

Reconnect recovery is deliberately narrow: public recent REST must still contain the exact trade immediately before disconnect and overlap the resumed public WS with matching IDs and canonical payloads. If not, the runtime stays blocked; an official historical archive or explicit new epoch procedure is required. Read-only unit tests do not count as a supervised disconnect/restart validation.
Three unsuccessful bounded reconciliation attempts cause a hard integrity fault; the process does not silently mark itself healthy. A manual restart is not itself proof that the gap was recovered—the same anchor and official-source checks still apply. Payload conflicts, late trades and official candle mismatches also require investigation before cutover.

The restored-only Shadow runtime now wires an hourly scheduler to committed state, the latest public mark, the append-only hourly claim and SMTP. It verifies SMTP before starting Shadow, requires the `node_hourly_reports` role grants, and halts Shadow if sending fails. Unit tests use an in-memory fake transport; no production mail has been sent. A zero-trade heartbeat is still formatted, and the database claim is at-most-once per UTC hour. The report timestamp is the actual generation time, while the durable claim is keyed to the UTC hour. Inverse BTC collateral is marked in USD, so USD equity can move with BTC price even when there are no closed trades; expectancy and PF use closed-trade USD results. SMTP failure after claim cannot safely be retried without a reviewed delivery/outbox protocol; operators must inspect claimed-but-unsent hours. Do not mark hourly reporting operationally ready yet.
